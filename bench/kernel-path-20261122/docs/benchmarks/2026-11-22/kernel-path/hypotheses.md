# Ben’s kernel and networking hypotheses

The accessible record of Ben’s 21 November research message identifies the items below, including `scx_bpfland`, a waking-socket scheduler, memory reclamation and the ArcBox comparison. The linked conversation did not expose the full original paste here. This map covers the recovered items and Ben’s subsequent steering. The experiment names resolve under `$RELAY/docs/benchmarks/2026-11-21` unless otherwise dated. Exact Git blobs and section names are in the [source manifest](sources.json). Decisions apply to the benchmark program. Product defaults are outside this experiment.

## Commands for the decisions

**Primary.** `python3 -B scripts/gamma_path_study.py replay --series path-confirmation`, `--series bridge-kernel` and `--series rps-rfs` read historical measurements. The [baseline and path commands](README.md#run-in-a-released-slot) include the slot, source, fixture and stock-policy gates.

**Size, relay and peer.** These commands print exact orders offline. For a separately reserved `size` run the owner’s driver accepts `--a "$SCOPE4" --b "$SCOPE6" --run --out "$NEW_RESULTS"`. The `peer` mode accepts corresponding four-vCPU scopes. Host-only `distribution` and `workers` isolate two different changes. The four-worker short screen raised fresh p99 from 19.5 to 30.5 ms on 32 ports.

```sh
python3 -B "$RELAY/scripts/relaybench/gamma_pilot.py" --mode size --seed 34199
python3 -B "$RELAY/scripts/relaybench/gamma_pilot.py" --mode peer --seed 34199
python3 -B "$RELAY/scripts/relaybench/gamma_relay_pilot.py" distribution --ports 32 --seed 34199
python3 -B "$RELAY/scripts/relaybench/gamma_relay_pilot.py" workers --ports 32 --seed 34200
```

**NIC, fixed workload and flows.** `sh scripts/kernel_path/guest-facts.sh` in the authorized guest produces `nic`. Collect before/after on the same boot and actual virtio interface for IRQs/GiB, drops, retransmits, softnet pressure and effective flags. `"$TOOLS/fixed" "http://$PUBLISHED_LOOPBACK" "$UNIQUE_MARKER"` runs the pinned HTTP workload. For later kernel experiments pair this client with the same process-counter sampler, idle/lease checks and per-arm proofs in the primary driver. The dedicated `kernel` and `policy` modes enforce candidate-specific attestations. [Exact later commands](README.md#kernel-and-scheduler-pilots-after-the-route-comparison) In a separately released `flows` screen, use `iperf3 -c 127.0.0.1 -p "$IPERF_PORT" -t 6 -P 1 -J` on an already-bound benign loopback fixture, repeat with `-P 4`, then add `-R` to each. These supplementary runs cannot substitute for the matched HTTP pilot.

**Quota.** The only candidate is upstream `scx_bpfland` v1.1.4 at `e7b3a219617472cf78880ac424714e52c932db61`. Use an already authorized disposable `full-scx` boot. The trusted `$Q/policy-build.json` supplies `program`, `source_revision`, `executable_sha256` and exact live `ops`. The guest owner captures `sha256sum /proc/"$POLICY_PID"/exe` in `$Q/active/executable.sha256`. Each phase uses a preloaded digest-pinned Alpine image. The existing quota probe creates only networkless test jobs.

```sh
# Use PHASE=before and fallback with POLICY=fair. For active use the exact attested ops.
curl --noproxy '*' -fsS --unix-socket "$OCI_SOCKET" http://localhost/oci/v1/kernel > "$Q/$PHASE/kernel-before.json"
python3 -B "$RELAY/scripts/check_worker_cpu_quota.py" "$DISPOSABLE_ENDPOINT" "$POLICY" \
    --image "$PINNED_ALPINE" > "$Q/$PHASE/quota.json"
curl --noproxy '*' -fsS --unix-socket "$OCI_SOCKET" http://localhost/oci/v1/kernel > "$Q/$PHASE/kernel-after.json"
# After all three phases on the same candidate boot, run the read-only verifier.
python3 -B scripts/kernel_path/verify_quota.py "$Q"
```

The gate recalculates CPU seconds per second from cgroup usage and elapsed time. Both 2-CPU probes must reach 1.25 and the half-CPU sample must measure 0.40–0.60. It verifies two distinct sibling leaves, busy-task membership, stable ops/enable sequence, 1 GiB/512-PID controls, active transition and return to fair scheduling. A failure makes the policy ineligible. Qualify fallback first and repeat the live quota/readback on re-entry before timing any EEVDF/bpfland pairs. The running stock kernel cannot supply this qualification. **Warm, disk and SQL.** The `warm` reproduction uses `python3 -B scripts/profile_warm_edit.py run` with `--clients 1 16 --blocks 6 --seed 20261122 --storage-probes` and the documented worker/build/fixture inputs. Add `--workspace-parent "$EXISTING_CONFIGURED_DIR"` for an authorized virtiofs share. `disk` uses `python3 -B scripts/ci_storage_probe.py "$DISPOSABLE_APFS_DIR" --method clone --rounds 16`, then `--method private`. The in-job lower-layer cases use the same probe. For a dedicated compatibility reservation, `sql` is `MICROPOD_CI_POSTGRES_PATH=bridge bash ci/worker-pipeline.sh all "$DISPOSABLE_ENDPOINT"` in the relay checkout. `python3 -B scripts/bench_docker_launch.py plan` retains the native-vs-stock three-arm Alpine control.
