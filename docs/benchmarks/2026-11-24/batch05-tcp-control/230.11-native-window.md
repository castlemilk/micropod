# Moving the Darwin relay’s 512 KiB receive-buffer request past the handshake

24 November 2026 · 230.11 · Local/host-only · Raw-verified · macOS 26.5.1, Darwin 25.5.0, arm64, Apple clang 21.0.0 (clang-2100.1.1.101).

Both arms ran the actual `dial_guest` from Micropod `7d9b565173a901cb18942e00384838da96e0ba98` against one same-process private IPv4 loopback listener. The control used `mp_tcp_relay_bound_guest_window` to request 524,288 bytes before connect, as in the bounded mode. The candidate deferred that same request until the server had accepted the connection. Both used the same relay preparation, TCP_NODELAY, data queue and receive code. The harness used blocking reads after the handshake and verified 32 consecutive 16 KiB chunks and both EOFs per connection. The VM, production service and relay polling loop were outside this fixture.

| Handshake or delivery observable | Before connect | After accept |
| --- | ---: | ---: |
| SO_RCVBUF after accept, before any candidate change (B) | 538,956 | 408,300 |
| SO_RCVBUF after applying the requested setting in both arms (B) | 538,956 | 524,288 |
| Receive window scale on dialing relay and send window scale on accepted socket | 3 | 6 |
| Receive window on relay and send window on accepted socket before payload (B) | 524,280 | 408,320 |
| Payload delivered per connection (B) | 524,288 | 524,288 |
| Sender-reported retransmitted packets, summed | 0 | 0 |

All 16 pairs repeated these values exactly. The 32 first attempts used eight blocks per order, shuffled with Python Random(23011). Both endpoints reported window scaling enabled. Each arm verified 8 MiB total. The counts represent one kernel and one listener. The result has no interval estimating between-machine variation. Wire packet loss, throughput, fresh p95/p99, CPU/GiB and runnable time were unmeasured. TCP_CONNECTION_INFO records negotiated scale and current windows. No SYN packet capture was taken.

**Verdict.** Moving the same receive-buffer request changed both negotiated scaling and the initial advertised credit on the native relay path. The later setting gave the sender 115,960 fewer bytes of initial credit. A request for 512 KiB alone does not identify the stock policy. Preserve pre-connect placement for the revised baseline. For a future window-size trial, record both endpoints’ scale, advertised credit, actual receive buffer, byte delivery and fresh tails on the qualified service path.
