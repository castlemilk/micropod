# Idempotent requests on the Darwin TCP opening handshake

24 November 2026 · 231.05 · Local/host-only · Raw-verified · macOS 26.5.1, Darwin 25.5.0, arm64, Apple clang 21.0.0 (clang-2100.1.1.101). Micropod checkout `7d9b565173a901cb18942e00384838da96e0ba98`; stand-alone native client/listener fixture `socket_trials.c`, SHA-256 `5b71dffe3c5d07c0505d079191e7fc7259fb78cb944aaf808f0d736ff45c2126`.

One private IPv4 loopback listener had TCP_FASTOPEN enabled after listen, verified on every arm. Both clients enabled TCP_NODELAY. The control established an ordinary TCP connection before its write. The sole treatment submitted the identical, known-idempotent 20-byte GET /id request with connectx and CONNECT_DATA_IDEMPOTENT. Each arm byte-checked the server’s request, the client’s 256-byte response and both EOFs. Raw kernel observations come from TCP_CONNECTION_INFO on both endpoints. The production dial waits for the guest handshake before reading client data.

| Outcome on a new connection | Stock connect then write | Idempotent connectx |
| --- | ---: | ---: |
| All request bytes received, response verified and EOF | 16/16 | 16/16 |
| Kernel recorded SYN data sent, acknowledged and received | 0/16 | 15/16 |
| Server issued cookie and client received it | 0/16 | 1/16 |
| Client or server reported retransmissions | 0/16 | 0/16 |
| Kernel flagged lost SYN, invalid/wrong cookie or disabled heuristics | 0/16 | 0/16 |

Sixteen randomized order-balanced pairs (eight of each order, Python Random(23105)) shared one endpoint. On the first candidate attempt, connectx accepted all 20 bytes, the kernel obtained a cookie, and no SYN data was sent. All 15 subsequent candidate attempts sent data on SYN; all three transport flags agreed on every arm. The shared cookie cache creates dependence across attempts. These denominators characterize this observed sequence and do not estimate a general success probability. Retransmission counts come from the two socket endpoints. On-wire drops, fresh p95/p99, throughput, CPU/GiB and runnable time were unmeasured.

**Verdict.** Native Fast Open can carry a warm idempotent service request on the opening handshake. A successful connectx call alone would misclassify the cold attempt. The generic published-TCP relay cannot establish that the first opaque bytes are replay-safe. Keep ordinary connect for the stock relay. If a protocol-aware idempotent endpoint is available on the authorized VM, distinguish cookie acquisition from warm SYN-data delivery and check end-to-end fresh tails, drops and CPU before making a performance claim. Accurate ECN was outside this experiment.
