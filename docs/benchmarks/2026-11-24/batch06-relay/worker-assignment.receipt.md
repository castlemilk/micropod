**24 November 2026 · 230.02 · Assign new connections to the owner with the fewest live descriptors**

Local/host-only Darwin 25.5.0 arm64 fixed-work fixture. Used the real dedicated C data owners, target leases, connection pump and half-close handling from Micropod `17bcd4355234b11da3a7a1da2ded52f4dc20f5d1` on anonymous socketpairs. Changed only assignment. Stock used the actual per-lease rotating selector. The prototype started from the same rotating preference and selected the owner with the fewest live reservations. The fixture serialized reservation updates at admission and retirement. It models timely notification of closes. It does not measure synchronization costs in a multithreaded implementation.

One logical lease, 32 long-lived connections and 240 serial short replies in every cell. Both arms were tested with two and four owners, each held fixed within its comparison. Six workload/owner combinations ran twice per arm in ABBA order. With all long-lived flows admitted before the first short request, allocation stayed 16/16 on two owners and 8/8/8/8 on four. In the synthetic turnover workload, one short request retired between each long-lived admission. The two-owner distribution changed from 32/0 to 16/16. Four owners changed from 16/0/16/0 to 8/8/8/8. Each long flow delivered 32 KiB. With the same long lifetimes and alternating 32 KiB and 17-byte payloads, both rules assigned equal connection counts but retained the same two-owner byte imbalance of 524,288 vs 272 B.

Every arm verified all 2,880 short replies, all long payloads, 3,264 reverse markers, both half-closes and all 3,264 flow retirements. Repeats agreed exactly. Counts describe fixed inputs. TCP loss, throughput, scheduled-arrival p95/p99, CPU/GiB and runnable time were unmeasured.
