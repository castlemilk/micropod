# Container exit notification on Gamma’s CI worker

Micropod’s native runner now waits for a containerd task-exit notification. With 64 resident containers, the stock runner made 317 unsolicited CRI status calls per second while idle and 315 per second during builds. The candidate recorded zero in both measurements. Eight explicit Docker stats requests still produced eight CRI status calls. The runner queries CRI at startup and exit for the authoritative status, drains the log before returning, and resumes timed status checks if the waiter fails or CRI is still committing the exit. ## Performance under current host load

Each engine ran 32 isolated client/service pairs. Eight clients concurrently vetted, tested, compiled, linked and ran two revisions of a Go project. The 32 warmed HTTP clients offered 64,000 requests per second. Four fresh Micropod boots alternated the stock and optimized runners in opposite orders across two seeds. Each boot contributed four paired dense windows. The signed host executable, Virtualization.framework backend, Linux kernel, four-vCPU and 4 GiB worker, image, and workload stayed fixed. Host idle ranged from 75% to 93% immediately before the four boots. Scheduled latency starts when each request is due. Post-dispatch latency starts when the client issues it. Against Micropod stock, the median matched changes were −25.0% for scheduled p95, −31.6% for scheduled p99, −23.7% for post-dispatch p95 and −1.46% for build time. The scheduled p95 improvement was 31.7% in the first seed and 1.6% in the reversed seed. Build time rose 0.53% in the first seed and fell 2.67% in the second. The two engines completed all 3,072,000 scored requests, 256 two-revision builds and 4,096 workload tests between them. For requests in each engine’s 94th–96th percentile band after dispatch, the mean time difference from Micropod to OrbStack fell from 303 to 265 µs. The portion from the client’s first-response-byte callback through completion stayed nearly constant at 180 and 177 µs. This interval includes transport processing and time until the calling goroutine resumes. Micropod’s post-dispatch p95 improved in the first seed and regressed in the second. ## Docker behavior at 112 resident containers

Two separate diagnostic boots each added 48 small containers after the timed work and inspected the exact 112 running container IDs. On both workers, two clients registered for the next exit before the container started, saw exit code 43, and a log subscriber received live stdout and stderr followed by the exact final bytes without newlines. Six overlapping foreground commands returned the expected outputs and exit codes, removed themselves, and a killed container reported 137 through both wait and inspect. The optimized guest still reported 1.69 GiB available at 112 residents and zero OOM kills. The positive controls and the targeted Linux tests also passed. Kernel uprobes counted entries to the actual compiled runner functions on all four guest CPUs. Each of the seven phases retired its 12 counter descriptors. The optimized binary still entered its regular-file log drain 314 times per second when idle and 317 times per second during builds. Its Docker engine made 322 read syscalls per second when idle, down from 544. Both private containerd endpoints sent an initial HTTP/2 settings frame with a 16 KiB maximum frame size and no concurrent-stream limit advertised. ## Worker drives, excluded attempts and baseline

Each fresh native worker in the Gamma fixtures gets a dedicated 16 GiB APFS sparse image for its configured 6 GiB disk. The provisioner creates `.fseventsd/no_log` and `.metadata_never_index`, and verifies Spotlight before timing. After the worker shuts down it ejects the writable image and remounts the same volume read-only to check the persisted journal and Spotlight state. All nine new worker volumes in this stage had zero FSEvents journal files and bytes and disabled indexing and searching. Each backing image was then ejected and removed. The complete audit verified 32 dedicated volumes, 270 retired fixture scopes and all 24 original baseline files plus their preserved copies. [Provisioner](worker_apfs_drive.py) · [Post-eject evidence and cleanup audit](sibling-output-polling-cleanup.json)

The first preflight stopped before timing because the verifier counted three passing Go subtests as top-level tests. It now checks the five roots and three subtests separately. A later attempt stopped when an unrelated OrbStack workload appeared and was rerun on a fresh drive. One qualified boot logged a final blocker-free host sample 7.3 seconds after the last measured wave, following a paired observation of zero running peer containers. Its peer row was missing. The comparison retains that host row and all 45 earlier pairs.
