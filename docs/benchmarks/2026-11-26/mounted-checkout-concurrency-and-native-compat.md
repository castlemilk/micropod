# Stock Testcontainers and concurrent mounted checkouts on Gamma

Eight stock Testcontainers clients reached all eight HTTP-ready services in a median 948 ms on Micropod and 1,425 ms on OrbStack. The new native runner fixes concurrent Ryuk creation and session-owned cleanup. On the larger Mac checkout, eight simultaneous stock Git checks still took 319 ms on the retained Micropod stack and 139 ms on OrbStack. Two guest request-layout trials and a host coalescing trial left that gap open. [Scored runs and cleanup](mounted-checkout-concurrency-and-native-compat-gamma.json) · [Raw receipts and exact sources](mounted-checkout-concurrency-and-native-compat-gamma-receipts.tar.gz)

The production target is a stock Docker client connected to the managed Micropod machine socket. The November 25 B3 study established the direct-HVF networking baseline. B4 subsequently demonstrated zero-`vmnet` egress and measured cubic/fq IPvlan throughput. This qualification exercises the native containerd-backed Docker API and eight independent CI clients. The raw checkout uses stock Git, a Mac-authored index, 1,058 source files and the same image and source digests on both engines. ## Native Engine and stock Go Testcontainers

The fixture compiles with the repository sample's Go module and dependency lock. It uses Testcontainers for Go v0.40.0, the stock Docker Go SDK and the published arm64 Ryuk v0.13.0 reaper. The client addresses each engine's explicit Unix socket and gives Ryuk its ordinary in-container socket path. The HTTP check reads a unique body through a published loopback port. An early attempt invoked an HTTP applet absent from the Alpine image on both engines. The matched fixture uses the image's available netcat listener. [Go fixture](../../../scripts/testcontainers-fixture/main.go) · [Qualification driver](../../../scripts/qualify_testcontainers_go.py)

Gamma built the Darwin arm64 client with Go 1.27.2 and Docker SDK v28.5.1. From the phase worktree, the following builds the same fixture using the shared Go cache.

```sh
fixture=$(mktemp -d)
cp ci/samples/go-app/go.mod ci/samples/go-app/go.sum scripts/testcontainers-fixture/main.go "$fixture/"
(cd "$fixture" && CGO_ENABLED=0 GOWORK=off go build -trimpath -mod=readonly -o testcontainers-fixture .)
```

Runner `e7b6d60a49fe` compiles the name expressions once per list request, matches both bare and slash-prefixed Docker names, and selects a single named endpoint from that SDK request. Both engines then reused running and stopped containers with their original writable marker, matched the nine name-selector cases and served HTTP on the named network. The next stock request to attach a second network reached the native API and returned HTTP 501. The eight-service workload starts eight sibling Testcontainers clients from one parent, as happens with multiple Go test packages. They share one SDK session and one real Ryuk. The clock runs from the first client launch until the last service has passed its published HTTP check. Once all eight are ready, the harness verifies eight distinct container IDs and ports, the eight expected response bodies, the shared session, and the live Ryuk's image. It then releases the clients and times automatic removal through HTTP 404 for all nine containers. The Alpine and Ryuk root filesystem layers and repository targets match across engines. Micropod and OrbStack expose different kinds of immutable image ID in their inspect responses, so each engine is checked against its own preflight ID. ## Mounted checkout experiment

The retained control uses signed VMM `f0747277714e`, the `61b4e143b260` kernel, a single workspace request queue and background workspace release. The source tree contains 19,326,482 bytes. Each single-job pair runs stock Git status, a Go build and three uncached Go tests with two CPUs and 1,536 MiB. In the eight-job comparison each container has its own index mount, half a CPU and 256 MiB. All eight begin from a common barrier. Each workload has four alternating Micropod/OrbStack pairs. The admission rule uses two consecutive one-second samples with at least 90% host idle before the workload. The experiment records actual host load throughout.

The first guest experiment uses a single ARM64 Image, `92a0c68ab8a3`, with the original B5 configuration verified against its embedded config. Both arms disable inline completion. The switch packs the FUSE request header with one small input and packs the reply header with a fixed result. Page-backed reads still use the destination folios supplied by Linux. The buffer keeps the read and write DMA regions on distinct cache-line boundaries. Other request shapes and allocation failure take the ordinary path.

The trace matched every main-thread Git submission to its FUSE reply by connection and request ID and to its scatterlist by request pointer. All 1,076 OPENs changed from two readable and two writable buffers to one of each. All 1,131 READs shed a readable buffer. All 1,504 enabled LOOKUPs still used two buffers in each direction. Linux constructs LOOKUP from a prefix, the file name and a terminating NUL. The first candidate's single-input check sent them down the ordinary path. The first offline reducer also missed records with a trailing space. Reprocessing the original bytes recovered those records. The follow-up kernel accepts bounded multi-part inputs and keeps the same fallback. [Pinned Linux LOOKUP construction](https://github.com/gregkh/linux/blob/v7.3.5/fs/fuse/dir.c#L341-L356) · [Follow-up kernel patch](../../../ci/patches/virtiofs-workspace-compact-requests.patch) · [Kernel builder](../../../ci/patches/build-virtiofs-workspace-compact-kernel.sh) · [Layout trace analysis](../../../scripts/analyze_virtiofs_request_layout.py)

The host experiment uses signed VMM `d256db0c6f12` with the retained kernel. Its optional workspace queue examines up to 32 already-posted requests. Consecutive equivalent lookups can share one host observation. Read sharing requires ordinary read-only handles on the same local APFS volume, the same file identity, range, flags and compatible lock ownership. The driver reports the number of operations actually saved. The tested implementation and unit cases are preserved in the source receipts.

Over the enabled worker's lifetime, this avoided 6,521 of 129,154 eligible LOOKUP observations and zero of 62,840 eligible READ observations. The 442,402 batches included 48,557 with multiple requests. Linux supplies a process-specific lock owner for direct reads. The host preserves that distinction. Enabling the candidate moved the eight-job median from 303.9 to 322.6 ms. OrbStack also slowed between those windows, and the enabled density run began under ambient load. The experiment stays in the benchmark archive. Review additionally found that overlapping guest-provided response ranges could change the order in which header and payload bytes landed under the experimental option.

### Where the eight Git jobs spend time

A separate run traced the stock Git executable with Trace2 and collected child CPU, faults and context switches for each process. It used the retained kernel and VMM and the original Mac index. With a four-CPU kernel build active and 2.95% whole-host CPU idle during the trace, all 32 processes on each engine reported 1,058 preload stats, 1,058 refresh stats, 1,058 content scans and 181 directories visited. The median refresh region took 984.0 ms on Micropod and 217.2 ms on OrbStack. Median voluntary context switches were 5,387.5 and 3, and major faults were 141.5 and 0. Median cgroup throttled time was zero on both engines. These process-wide counters cover the entire Git invocation. The four-core compile and tracing overhead are included in these diagnostic times.

After the compiler exited, a fresh worker with the identical retained stack and trace driver repeated the experiment. All 22 quiet preflights missed. The separately labelled ambient repeat measured 42.74% host idle. Every Git process still scanned all 1,058 files. The median refresh took 330.8 ms on Micropod and 135.0 ms on OrbStack, and the eight-process wave took 465.7 and 183.9 ms. Median voluntary switches were 5,315 and 3, and major faults were 144 and 0. Each engine removed its eight diagnostic containers. The uninstrumented stock Git timings are in the end-to-end table above.

Git 2.39.5 reads ordinary files up to 32 KiB into a buffer in this indexing path and privately maps larger files. This fixture has 932 files at or below that cutoff and 126 larger files. A trace that attributes wait time and faults to individual reads and mappings can distinguish where the engine spends its time.
