## Metadata and failure handling

Micropod traverses recorded `org.mobyproject.image.parent` links on configuration-ID records or digest references bound to their targets. It uses each container's saved image ID across retags. A parent label present solely on a mutable tag is ignored because its target can change. Ordinary imports through the containerd archive importer leave Docker archive `Parent` information unavailable. Parent matching requires a stored link, and shared filesystem layers alone leave images independent. [Ancestry implementation](../../../guest/runner/docker_image_ancestor_linux.go) · [Containerd 2.4.2 archive importer](https://github.com/containerd/containerd/blob/v2.4.2/core/images/archive/importer.go)

An unavailable image service produces an HTTP 500 Engine error, consistent with native image inspect and history. The focused Linux suite verified that an outage fails the request even after another ancestor selector resolved. Moby v27.5.1 skips errors from resolving a selector and propagates errors from traversing its descendants. All 17 native ancestor subcases passed, and the combined Linux suite recorded 406 passes and five environment-dependent skips, including subcases in its counts.
