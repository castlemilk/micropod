# Stock Docker builds and host-mounted CI on Gamma

The native Micropod Engine now accepts stock Buildx through the same Docker socket used to start containers. The mounted-checkout experiments still favor OrbStack on the 1,058-file repository. The production settings remain one VirtioFS workspace request queue, standard Linux completion placement and automatic guest CPU placement. [Gamma scorecard](workspace-queues-and-native-buildx-gamma.json) · [Raw measurements, source and cleanup](workspace-queues-and-native-buildx-gamma-receipts.tar.gz)

## Native Docker builds

On native guest `e00d6da9b0b2`, the Engine returned HTTP 501 for the BuildKit upgrade. Stock Buildx selected its container driver, pulled a builder and failed when Micropod rejected its cgroup parent. The new guest delegates the stock driver's control connection and reverse file-transfer session to the managed BuildKit daemon. It translates the engine's image exporter, canonicalizes tags in containerd and waits for the newly published image to become visible to the container runtime. Local exports and cache hits use the same authorized socket. [Native bridge](../../../guest/runner/docker_buildkit_linux.go) · [Stock driver](https://github.com/docker/buildx/blob/v0.38.1/driver/docker/driver.go) · [BuildKit control and session protocol](https://github.com/moby/buildkit/blob/v0.34.1/api/services/control/control.proto)

Two earlier candidates exposed separate identity bugs. Guest `084870` created a shortened repository name that containerd's runtime could resolve only by ID through the Engine. Guest `5f7e2b1733f4` supported immediate named runs, independent retags and unnamed loads. Its stock `--iidfile` still contained the manifest digest, which returned HTTP 404 when passed to native image inspect. A third guest verified the local config and manifest before returning success. Stock Buildx v0.38.1 detects the BuildKit containerd snapshotter, deliberately discards the config digest for that driver, and writes the manifest or index digest. The correct compatibility test is to pass the literal contents of the file back to the Engine for an immediate inspect and run. [Stock driver feature detection](https://github.com/docker/buildx/blob/v0.38.1/driver/docker/driver.go#L78-L103) · [Stock result selection](https://github.com/docker/buildx/blob/v0.38.1/build/build.go#L1025-L1033) [Stock reproducer and regression driver](../../../scripts/qualify_native_buildx.py) · [Build and wire receipts](workspace-queues-and-native-buildx-gamma-receipts.tar.gz)

Native container listing now accepts Docker's image-ancestor filter. It follows explicit parent links on immutable image records across retags and excludes unrelated images that share layers. The reference cases include a real three-generation stock classic build on OrbStack. Two raw cross-engine ID queries expose the different image IDs each engine advertises. ## Published image identity

The native lookup first checks the authoritative config-ID record. For a full manifest or index digest it asks containerd for that exact local target, verifies the managed config record and confirms the runtime can resolve it. A stock client can use the digest from its IID file to inspect, tag and run the image immediately. A default `docker build` adds an attestation to the index. Removal by the native config ID also handles a verified index with one runnable ARM64 manifest and its Buildx attestations. The deletion path retains named and pinned references and checks for containers using the config ID, the outer index or the runnable child digest. The worker reads bounded metadata for this check. [Image lookup and removal](../../../guest/runner/docker_image_id_delete_linux.go) · [Attestation index verification and tests](../../../guest/runner/docker_image_id_attestation_linux_test.go)

A separate default-provenance run on stock OrbStack confirmed that its IID file contained the outer OCI index and that it could run the image by that ID. Its `image inspect` returned that index as the image ID. Micropod reports the runnable config ID when inspecting the same kind of reference. Exact comparisons use these separately recorded identifiers. [Stock client traces and recovered OCI descriptors](workspace-queues-and-native-buildx-gamma-receipts.tar.gz)

### CI image selection and cleanup

A post-run inventory found that the native `GET /images/json` returned ten unrelated image rows for a label that matched nothing on OrbStack. The new differential loads three uniquely labeled images on each engine, checks presence, exact values, conjunction and empty values through the API and stock CLI, and counts every returned row. It verifies unrelated image IDs and the preloaded source after cleanup. The stock compatibility target for an absent label is an empty list. [Pinned API driver](../../../scripts/qualify_engine_api.py) · [Docker filter semantics](https://github.com/moby/moby/blob/v27.5.1/api/types/filters/parse.go)

The first implementation filtered on CRI labels correctly. After removal, three of the fixture images still appeared in that cache even though the native Engine returned 404 for every tag, config ID, manifest ID and raw or normalized import digest. A fourth row belonged to a live untagged image left by an older Buildx test. The qualifier now checks that exact owned ID after removing the tag. The native engine verifies its inventory against the namespaced containerd metadata store before serving the list. ## Workspace queues and guest completion

Four alternating engine pairs per setting ran the same stock Git, Go build and Go tests on a 1,058-file Mac checkout. In a separate density test, eight stock Git processes shared the checkout and overlapped in every scored wave. The queue comparison used identical VMM and kernel binaries for both arms. The table shows median wall time in milliseconds. [Raw runs and host load](workspace-queues-and-native-buildx-gamma-receipts.tar.gz)

| Workload | Micropod, one queue | OrbStack in that window | Micropod, four queues | OrbStack in that window |
| --- | ---: | ---: | ---: | ---: |
| Warm Git, build and test | 834.23 | 666.39 | 831.62 | 657.10 |
| Edited Git, build and test | 2,034.61 | 2,002.71 | 1,992.94 | 1,973.10 |
| Eight concurrent Git jobs | 313.30 | 139.55 | 310.78 | 136.67 |

The paired Micropod/OrbStack ratio rose from 1.257 to 1.267 for the warm job and from 2.245 to 2.275 for the eight-job wave. The VMM exposed four normal request rings and Linux mapped one per guest CPU. A single host worker served those rings. Raising the queue count alone did not narrow the relative gap. Multiple rings passed held-file, splice, exact-mtime edit and final-unmount checks. Eight concurrent writers and readers also passed an fsync and remount diagnostic. The four-queue topology remains available for experiments with `MICROPOD_VIRTIOFS_WORKSPACE_QUEUES=4`. [Topology, source replay and 51 Rust checks](workspace-queues-and-native-buildx-gamma-receipts.tar.gz)

A second one-queue control met the quiet admission rule of two consecutive one-second samples with at least 90% host idle. Its four-pair medians were 857.05 versus 671.59 ms warm and 2,048.29 versus 2,026.55 ms edited. Both queue counts therefore have quiet-admitted single-job measurements. The median paired Micropod/OrbStack warm ratio was 1.270 with one queue and 1.267 with four. The edited ratio was 1.020 and 1.025. The host averaged 79.27% and 79.54% idle during timed work. The eight-job density figures above retain their original admission conditions. [Admission samples and four alternating pairs](workspace-queues-and-native-buildx-gamma-receipts.tar.gz)

On a second, matched kernel, routing single-queue completion toward the submitting guest CPU increased warm job time from 828.00 to 860.10 ms. Eight Git jobs took 310.93 and 315.89 ms. A pinned trace independently verified that completion moved to CPU 1 and that median dispatch cost rose from 2 to 10 µs. Keep this option off. The next filesystem experiment should reduce the number or cost of synchronous host file operations. It must retain the held-descriptor, concurrent writer, mmap, splice and last-unmount checks. [Kernel source, per-operation timings and workload medians](virtiofs-workspace-local-completion.md)

The previous combined worker did beat OrbStack on a seven-file checkout in eight simultaneous warm Git/build/test jobs, 381.9 versus 417.7 ms, and in sixteen warm jobs, 816.2 versus 851.6 ms. Sixteen edited jobs split two wins per engine. These jobs include compilation and tests, whereas the eight-job row above times stock Git on the larger checkout. [Resource limits, overlap and comparable workloads](native-registry-and-mounted-ci.md#eight-and-sixteen-ci-containers-on-the-combined-engine)

## Worker lifecycle

An intermediate `a956b866` first boot exited with engine status 1 immediately after successful offline network package installation and before containerd emitted startup logs. Its supervisor restarted it, and the worker was excluded under the clean-first-boot rule. An independently created volume with the same binaries booted on the first attempt. Both final inventory candidates also booted without a restart. The rejected console identifies the startup interval but does not record the failing command. A separate unscored four-queue remount diagnostic also preserved its rejected first attempt. [Worker consoles, supervisor events and clean retry records](workspace-queues-and-native-buildx-gamma-receipts.tar.gz)

All 18 worker drives and the staging drive were remounted read-only for verification. Spotlight indexing was disabled, and each APFS volume had zero FSEvents journal files and zero journal bytes. All 19 drives were removed, the private OrbStack resource was cleaned up and its pre-existing base image was preserved. The raw archive contains 721 independently verified entries. The final runner, signed experimental VMM and guest kernel are retained with their digests. The November 24 baseline manifest verified all 24 original files and all 24 preserved copies.
