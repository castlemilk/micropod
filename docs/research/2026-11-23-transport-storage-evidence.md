| Project and cache placement | The worker reuses an ordered-journal ext4 disk. A configured Mac workspace uses a shared directory, and images and volumes live on ext4. The previous ext4 test changed fsync batching on one VM, checked barriers and counted write sectors and flushes. It did not compare placements. | Idle memory returned to the host | Worker boot enables PSI. The guest service reports available memory, OOM kills and CPU, memory and I/O pressure. The profiler already records guest memory and disk changes during workloads. Apple exposes a traditional virtio balloon, and a target adjustment requests guest cooperation. The reviewed worker boot path sets a fixed budget and has no balloon policy. ## Custom virtio transport and a second VMM

**Custom device.** Apple exposes `customVirtioDevices` starting in macOS 27. The recorded Gamma run used macOS 26.5.1. A device experiment needs a confirmed supported Mac and SDK. In the pinned dependency, `VZVirtualMachineManager.create` passes configured extensions to the VZ instance. A `VZInstanceExtension` can modify the device configuration before validation. The existing Micropod host path already has tests for byte preservation, simultaneous send and receive, half-close, backpressure and port revocation. [Apple availability](https://developer.apple.com/documentation/virtualization/vzvirtualmachineconfiguration/customvirtiodevices.md) · [Recorded Gamma environment](../benchmarks/2026-11-20/worker-profile/immediate-writes.md) · [Pinned VZ manager](https://github.com/apple/containerization/blob/c0185aea5c04fcd4d1cfe9359e0066a380835403/Sources/Containerization/VZVirtualMachineManager.swift) · [Pinned VZ instance](https://github.com/apple/containerization/blob/c0185aea5c04fcd4d1cfe9359e0066a380835403/Sources/Containerization/VZVirtualMachineInstance.swift) · [Relay contract tests](../../Tests/MicropodRuntimeTests/NativePublishedPortsTests.swift)

First reproduce the end-to-end ceiling on the released stock fixture. On a separately released supported host, capture a fresh stock control before trying a device so that the OS upgrade does not become an experimental variable. Start with one queue in each direction and a bounded buffer. Check queue exhaustion, disconnects, reattachment and byte integrity before benchmarking. Measure fresh-request p95/p99, failures, bulk throughput and host CPU per GiB with the same request mix. An isolated device bandwidth result cannot establish published TCP throughput.

**Second VMM.** The upstream manager protocol admits other implementations, but its Cloud Hypervisor manager compiles only on Linux. On macOS, Micropod instantiates the VZ manager directly and casts to `VZVirtualMachineInstance` to repair worker networking. The port broker, guest agent, block mounts, shared-directory semantics and NIC recovery all need coverage before a substitute backend can run a comparable CI workload. [Manager protocol](https://github.com/apple/containerization/blob/c0185aea5c04fcd4d1cfe9359e0066a380835403/Sources/Containerization/VirtualMachineManager.swift) · [Cloud Hypervisor platform guard](https://github.com/apple/containerization/blob/c0185aea5c04fcd4d1cfe9359e0066a380835403/Sources/Containerization/CHVirtualMachineManager.swift) · [Current worker assembly](../../Sources/MicropodRuntime/SandboxVM.swift) · [VZ-specific repair](../../Sources/MicropodRuntime/CIWorkerNetwork.swift)

Defer backend implementation until a repeatable, attributed limit survives the supported transport experiments. The smallest prototype would boot the same kernel, mount a disposable disk and round-trip the guest agent on an approved host. Subsequent qualification must independently exercise network recovery, share isolation and restart before timing a full worker.
