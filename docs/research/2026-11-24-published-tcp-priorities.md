# Micropod performance priorities after the Gamma peer holdout

24 November 2026 · Apple Silicon · OrbStack 2.2.5 · one published TCP port

Micropod delivered **8,046.4 MiB/s** against OrbStack’s **7,207.3 MiB/s**, with higher throughput in **16 of 16** controlled pairs. The median within-pair lead was **11.67%**, with a paired bootstrap 95% interval of **11.25–12.62%**. The next objective is to reduce the time for a new connection to receive its first small response while retaining this bulk throughput. [Replayed holdout](../benchmarks/2026-11-24/standard-peer-and-read-size/peer-verified.json) · [Admission and interface audit](../benchmarks/2026-11-24/standard-peer-and-read-size/peer-audit.json)

| Per-arm median or all scored attempts | Micropod | OrbStack |
| --- | ---: | ---: |
| Fresh-request p50 / p95 / p99, ms | 6.577 / 9.940 / 11.023 | 2.543 / 5.239 / 8.048 |
| Full-invocation host process CPU-seconds per bulk GiB | 0.556 | 0.978 |
| Runnable wait, thread-seconds per wall second | 0.647 | 1.636 |
| Fresh requests completed / offered | 3,840 / 3,840 | 3,840 / 3,840 |
| Bulk reopens / recorded interface drops | 0 / 0 | 0 / 0 |
| Share of bytes delivered by the slowest eight of 32 streams | 24.94% | 24.62% |

Both engines used four vCPUs, 4 GiB VM allocations, the same arm64 service image and four-CPU service limit. Each six-second window ran 32 sustained streams and 240 fresh requests. Each of the three warmup pairs preceded the 16 scored pairs. Entry required two reads of at least 90% host idle, with paired arms within five percentage points. The Micropod candidate used the Standard launchd role, two relay workers, 128 events per callback and a 256 KiB read cap. CPU covers the Micropod VMM and relay or the OrbStack helper. These measurements describe this host and traffic mix. [Run plan and hashes](../benchmarks/2026-11-24/gamma-local-peer/20261124T103005Z-run-8j1yw9d6/plan.json) · [Matched configuration](../benchmarks/2026-11-24/gamma-local-peer/20261124T103005Z-run-8j1yw9d6/fixtures-before.json)

Micropod’s **p50 exceeded OrbStack’s p95 in every pair**, by 0.591–2.115 ms. The median paired p95 gap was **4.598 ms**. Even if every Micropod request incurred its round’s maximum recorded dispatch delay, its post-dispatch p95 would still exceed OrbStack’s scheduled p95 by at least **3.580 ms** in every pair. Optimizing the client timer or redistributing bulk streams has little evidence behind it here. The available records cannot divide the remaining delay between the two TCP connections, relay scheduling and the guest service. [Per-pair analysis](../benchmarks/2026-11-24/standard-peer-and-read-size/latency-profile.json)

A separate four-pair run at natural host load gave Micropod **7,704.2 MiB/s** and OrbStack **7,166.8 MiB/s**. Micropod won three pairs, with a median paired lead of **7.48%**. Fresh p95 was **10.976 / 5.788 ms**. Both completed all 960 fresh requests per arm. This smaller replication shows why the controlled 11.67% lead should stay qualified by the host conditions. A second published-TCP workload changes the order for CI users. With 32 published services and 32 pre-created CI jobs dispatched four at a time, Micropod delivered 5,069 MiB/s and OrbStack 7,180 MiB/s. Fresh p95 was 54.2 vs 49.5 ms, with 480/480 successes and zero bulk reconnects on each engine. Both batches favored OrbStack. Direction 230.17 crosses the number of service destinations with CI activity to isolate this gap at fixed total streams and budget. ## Read-cap experiment completed during this study

One executable on Gamma ran both settings using Darwin kqueue and connected Unix stream sockets. Both arms used two workers, a 128-event callback budget, one logical listener, 32 bulk streams, 512 KiB socket buffers and 240 arrivals at 40/s. Runtime inspection checked the cap on each data owner. Three warmup pairs preceded eight balanced scored pairs. All 1,920 fresh requests per arm completed. The CPU measurement includes this fixture’s senders, receivers and relay in the same process. [Build, configuration and schedule](../benchmarks/2026-11-24/standard-peer-and-read-size/read-size-run/plan.json) · [Raw results and paired intervals](../benchmarks/2026-11-24/standard-peer-and-read-size/read-size-summary.json)

| Host relay metric | 256 KiB | 512 KiB | Median paired change (95% interval) |
| --- | ---: | ---: | ---: |
| Delivered MiB/s | 16,465 | 17,607 | +6.13% (+4.52% to +8.16%) |
| Scheduled fresh p95 | 14.46 ms | 18.65 ms | +30.90% (+24.85% to +34.47%) |
| Scheduled fresh p99 | 15.28 ms | 20.26 ms | +32.95% (+26.31% to +43.19%) |
| Process CPU-seconds per GiB | 0.292 | 0.258 | −10.86% (−13.09% to −9.76%) |

The 512 KiB cap increased both throughput and fresh p95 in every pair. That makes 512 KiB a candidate for a separate bulk-only test. For the current mixed workload, 256 KiB remains the better starting point.

The separate private-MTU trial (229.01) has a signed build and a service preflight. Check both routed MTUs, bidirectional DF, service-socket MSS, drops and actual receiver bytes on 1500 and 9000 before timing. An older offload screen measured 73.5 versus 4,920.3 guest TX kicks/GiB with TSO on and off. Its fixture and byte interval differ from the selected-build measurement in rank 5. [Private MTU preflight](../benchmarks/2026-11-24/batch11-private-vmnet-mtu/live-preflight.md) · [Historical TSO control](../benchmarks/2026-11-24/orbstack-rea/delivered-tx-kicks.json)

The stream-level replay found the fastest Micropod stream below the slowest OrbStack stream in both original 32-port CI batches. The runnable 230.17 study varies the number of active destinations and CI dispatch on a fixed resident set. A separate stock Linux test raised file-backed service delivery from 5,000 to 5,864 MiB/s by using sendfile for the same file. The matched follow-up reached 5,956 MiB/s on Micropod vs 7,798 on OrbStack. Micropod file throughput gained 18.73% over memory across four paired blocks, while its median fresh p99 rose from 85.83 to 99.92 ms. [CI service fanout and kernel measurements](../benchmarks/2026-11-24/gamma-ci-concurrency/fanout.md) The grouped HVF upload producer also completed eight write-threshold blocks. Fewer polls at 128 KiB coincided with a paired throughput change of −4.51% (3/8 wins). The result leaves the stock published-port relay unchanged. [Component measurements](../benchmarks/2026-11-24/gamma-ci-concurrency/low-level-results.md)

## Other Micropod workloads

The next user-visible networking target after published TCP is traffic between sibling containers. In a separate six-pair study, 32 established streams moving 6 GiB delivered 9,582 MiB/s on Micropod and 13,496 on OrbStack. Repeat that exact transfer at matched resources using numeric service addresses, then change bridge versus macvlan on Micropod alone. For Cuttlefish, measure cold checkout-to-first-build, shared-directory edit propagation and host memory returned after job exit. Use identical files and cache states, check the resulting build output, and track the next warm build after reclaim. These workloads have their own baselines. [Sibling benchmark](../benchmarks/2026-11-23/quiet-service-http.md) · [CI and storage scorecard](../benchmarks/2026-11-23/orbstack-scorecard.md) · [Linux virtiofs](https://www.kernel.org/doc/html/latest/filesystems/virtiofs.html)

Admitting all 32 gave 7.71 and 7.98 jobs/s and 33.36 and 24.16 ms. Two waves per setting support a wider balanced cap sweep. ## Work to defer

- The signed Micropod 7.3.5 kernel has KASLR enabled and already compiles out the standard arm64 KPTI transition. The remaining syscall question is whether the guest spends appreciable time in the actual call mix. Use the prepared probe and call counts if the guest profile warrants it. [Boot-bound configuration and probe](../benchmarks/2026-11-24/orbstack-rea/README.md#syscall-cost) · [OrbStack architecture](https://docs.orbstack.dev/architecture)
- The installed OrbStack helper contains direct Hypervisor.framework calls and VZ VM lifecycle code. REA establishes available implementations. The path for the scored published port remains unverified. The 32-endpoint result makes a copy and wait profile the prerequisite for integrated device work. A second VMM and a notification-only change still need product evidence. [Local binary and driver evidence](../benchmarks/2026-11-24/orbstack-rea/README.md) · [Matched hardware and Linux measurements](../benchmarks/2026-11-24/gamma-hypervisor/results.md) · [OrbStack developer account](https://news.ycombinator.com/item?id=48470145)
- Keep two workers for the selected configuration. Four lost all four controlled pairs under Interactive. The one-shot connect variant increased asynchronous lifecycle CPU by 4.57%. Wider receive steering previously spread softirq entries across vCPUs while reducing receiver throughput. Reopen these directions when phase and queue measurements identify a specific constraint.
