Three surfaces, one runtime

Micropod exposes the same container engine through a REST API (/v1/…), a Connect/gRPC service (micropod.v1.MicropodService), and an MCP tool server for agents. All are generated from source: routes from APIHandlers.swift, OpenAPI from protobuf via protoc-gen-connect-openapi, tools from a live tools/list.

REST API MicropodAPI · :8080

Plain HTTP/JSON surface used by the app, CLI and automation. ?force=true on deletes; log streams are SSE; the vsock route upgrades to a raw duplex stream for guest gRPC.

Connect / gRPC micropod.v1

The management service is defined in protobuf (proto/micropod/v1/api.proto) and served over Connect — one port speaks Connect, gRPC and gRPC-Web. Unary calls are ordinary POST /api/micropod.v1.MicropodService/<Method> with JSON bodies.

MCP tools micropod-mcp · stdio JSON-RPC

The MCP server exposes every operation as a tool over stdio JSON-RPC — this is what agents drive. Arguments are named in each description; volume_policy_set mutates the shared volume policy without a restart.
