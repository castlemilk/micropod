Micropod vs Docker Desktop, measured on the same Mac

We benchmarked Micropod's Docker Engine shim against Docker Desktop on the same Apple-silicon Mac, both engines warm, alpine:3.20 pre-pulled on both sides. API numbers are p50 over n=30; lifecycle over n=10. The result is not a uniform win, and we'd rather show the losses than hide them: Micropod's API surface is dramatically faster and it idles at a seventh of the memory, but a per-container micro-VM means a real kernel boot on every start — and that's a gap Docker's shared-VM model doesn't have.

A Kubernetes cluster that fits inside one Micropod micro-VM

kind puts Kubernetes inside a container inside Docker Desktop's VM. Micropod's new opt-in engine runs k3s as a single Apple micro-VM instead — a real kernel, a real vmnet address, and MetalLB LoadBalancer IPs that actually route on macOS. Measured on the same machine: 21s to a Ready node vs kind's 53s, ~700MB in use, 2.4s to resume — and services you can curl.

Shipping images to a micro-VM cluster without the slow path

The one genuinely bad number in the k8s engine wasn't Kubernetes at all — it was pulling images through the guest's vmnet NAT (13 minutes for MetalLB's 60MB). The fix is a small image pipeline: pull on the host, inject into the cluster's containerd, tag the qualified name. `micropod k8s load` — and the same op on Connect, REST, MCP, and the SDKs.
